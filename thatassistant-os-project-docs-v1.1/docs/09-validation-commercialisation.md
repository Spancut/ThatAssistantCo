# Validation and Commercialisation

## Current evidence status

The product is a deeply developed, research-informed hypothesis. It is not yet a market-proven SaaS.

## Evidence principles

Prefer:

- demonstrated current behaviour
- real workflow observation
- repeat usage
- paid continuation
- workspace expansion
- renewal

Do not treat compliments or hypothetical interest as proof.

## Primary pilot user

An established solo VA or EA-style VA who:

- manages approximately three to eight recurring clients
- has at least one year of client-delivery experience
- handles communication, meetings, projects or follow-up
- uses multiple tools
- values discretion
- can test approved, anonymised or representative work

## Validation stages

1. workflow interviews
2. workflow observation
3. concierge pilot
4. clickable prototype
5. narrow technical pilot
6. paid beta
7. controlled public launch

## Critical hypothesis

The system must make reviewing and using a plan faster and mentally easier than manually recreating the work.

## Early metrics

- client setup completion
- time to first value
- first workflow completion
- repeat weekly use
- first-pass approval
- correction rate
- follow-up reuse
- weekly update use
- trust
- willingness to pay
- AI and support cost

## Initial product strategy

Build one secure connected daily-delivery loop first:

```text
client setup
→ request intake
→ organised plan
→ decisions
→ approved work
→ waiting and follow-up
→ completion
→ client update
```

Then expand pillar by pillar based on evidence.

## Packaging direction

Core VA Edition should include foundational access to all seven pillars.

Plans may differ by:

- active client workspaces
- workflow volume
- storage
- automation allowance
- integrations
- reporting
- support

Specialist products:

- Social Media Operations
- Finance Administration
- Agency Edition
- Advanced Integration tier

Avoid lifetime deals, unlimited workspaces and unlimited AI before costs and usage are understood.
